# Канон — путь внедрения ОС у клиента

**Корпус:** `partner` · ось `member/`  
**Статус:** DONE  
**Аудитория:** partner уже на договоре / в пилоте  
**Опора:** partner SoT `01`/`02`/`04` + UI-детали только из `docs.ru/kb-wave1/`  
**Стиль:** `../00-STYLE-PARTNER.ru.md`

## 1. Роль подрядчика при внедрении

Контрибьютор / авторизованный партнёр **разворачивает и сопровождает** инстанс ОС у клиента (или страновой узел), пишет Updates по ТЗ, не подменяет собой правообладателя ядра и не ведёт Stage A продажи «за свой счёт» без модели из SoT.

> «Ваша задача — поднять рабочий контур клиента, настроить доступы и ИИ по Wave 1, передать клиенту понятный handoff. Продуктовые клики — из kb-wave1, не из памяти.»

## 2. Типовой путь (сценарий)

1. **Установка контура** — команда/требования из Wave 1 installation (`member/10`).  
2. **Безопасность и доступы** — RPC, auth, роли чата, кто редактор (`member/11`).  
3. **ИИ / знания** — провайдеры, RAG, голос, каналы (`member/12`).  
4. **Контент / юрпакет** — при необходимости конструктор пакета `/content/settings` (legal `80`).  
5. **Handoff клиенту** — доступы, что трогать нельзя, контакты поддержки (`member/13`).

Деплой DLE-контрактов и governance — по Wave 1 deploy/management; секреты (private key деплоя) **не** принимают в чат агента.

## 3. Границы

- Локальные ставки и объём договора с клиентом — из подписанного договора, не из чата.  
- Роялти Автору 1k/10k — `interested/03`; не путать с ценой клиенту.  
- Ask инвестора — не в ответах partner member.

## 4. Эскалация

Сбой установки на проде; спор IP/ROFR; клиент просит обойти EULA — сотрудник / Автор.
